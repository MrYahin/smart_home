# Актуальный план проекта

Обновлено: 26 октября 2026. Текущее состояние: [STATUS.md](STATUS.md).

## Принятые решения

- Рабочие проверки текущего контекста и истории подтверждены владельцем; переходим к документальным данным и тарифам.
- Используем PostgreSQL 18 в Docker на Debian. Supabase, Qdrant и RAG сейчас не нужны.
- Не создаём долгосрочный архив датчиков HA в PostgreSQL.
- Источники исторических документальных данных — PDF квитанций за два года.
- Гостевая SMB-папка подготовлена и проверена из Windows.

## Ближайший шаг: доступ n8n к входной папке

1. Подключить /home/yaha/utility-import/incoming к контейнеру n8n отдельным bind mount, сохранив n8n_data и существующие сети.
2. Проверить фактические UID/GID процесса n8n и настроить права совместно с Samba, без chmod 777.
3. Проверить чтение, создание и удаление тестового файла именно из контейнера.
4. Выбрать механизм запуска: ручной или расписание. Не допускать одновременную обработку одного файла и чтение незавершённой сетевой загрузки; это эксплуатационные меры, не проверки содержимого квитанции.

## Единый workflow «ЖКХ — Импорт PDF»

```text
PDF → извлечение текста → разбор полей → PostgreSQL
    ├─ успешная запись всех данных → удалить PDF
    └─ ошибка → зафиксировать причину, оставить PDF
```

По решению владельца исключены: ручное подтверждение, проверка ранее импортированного файла, хеширование для дедупликации, содержательные автоматические проверки и сводный отчёт по пакету.

Порядок реализации:

1. Проверить наличие energy.document_meter_readings и фактические ранее внесённые данные. Не объявлять успешной неподтверждённую ручную загрузку.
2. Подготовить таблицы документов, показаний и начислений с разделением периода квитанции, даты показания, расхода, ставки и суммы. Сохранять номер счётчика как текст. Индивидуальные и общедомовые показатели не смешивать.
3. Сначала проверить штатный Extract From File / Extract From PDF на образце. Для сканов/неподдерживаемого формата выбрать отдельную обработку. Облачную передачу содержимого согласовать отдельно.
4. Реализовать разбор полей. Отсутствующие сведения не придумывать: дата снятия, границы потребления и сроки действия тарифа могут оставаться неизвестными.
5. Сохранять данные одного документа одной транзакцией. Не скрывать конфликт через ON CONFLICT DO NOTHING с последующим удалением файла.
6. Фиксировать имя файла, этап, время и текст ошибки вне PostgreSQL при недоступности БД. Ошибку удаления после успешной записи различать с ошибкой записи.
7. Удалять PDF только после подтверждённого COMMIT. Не создавать постоянный архив оригиналов внутри workflow; владелец хранит исходные копии отдельно.
8. Реализовать на одном документе и затем обработать архив за два года. Работающий workflow экспортировать в GitHub без секретов и содержимого квитанций.

Риски принятых упрощений: распознанные неверно значения могут попасть в БД; повторная загрузка может привести к дублям или конфликтам; после удаления файла проверка требует отдельного оригинала. Ограничения БД остаются и обрабатываются как ошибки записи. Успешная запись не равна проверке корректности.

## Тарифы

- Ставки из квитанции хранить как применённые в документе.
- Отдельно создать справочник планов, версий с датами действия и расписаний зон с часовым поясом.
- Не выводить юридическую дату начала тарифа или часы зоны только из месячной квитанции.
- Не хранить документальный месячный расход как вымышленные почасовые показания HA.

## Последующие этапы

1. Energy — Calculate на JavaScript: расход, стоимость, сравнения; единицы, границы, сбросы, покрытие и контрольные примеры.
2. Прогноз до конца месяца с проверкой на прошлых периодах и указанием покрытия.
3. Energy — Proposals: факт, гипотеза, проверки и ожидаемый эффект.
4. Регулярные отчёты и уведомления. Отсутствие сводки импорта не отменяет будущие энергетические отчёты.
5. Контракты агентов и единый оркестратор, затем новые подсистемы.

Параллельно: каталог расчётных измерений и исключение двойного подсчёта; права вызова workflow и чата, sessionId/изоляция памяти; резервное копирование PostgreSQL и проверка восстановления; публикация безопасных SQL-миграций и Compose-конфигураций.

Коммиты документации не изменяют работающие контейнеры или n8n. Управление нагрузками и автоматизации требуют подтверждения; автоматический импорт PDF с удалением после успешной записи согласован отдельно.
