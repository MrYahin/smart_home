# Smart Home

Многоагентная система умного дома на базе Home Assistant и n8n. 

## Правила работы — читать первым

Перед разработкой прочитать [AGENTS.md](AGENTS.md). Пользователь решает, что и когда публикуется. Ассистент предлагает изменения; запись в GitHub допускается только по прямой просьбе пользователя на конкретное действие. Правила AGENTS.md этим обновлением не изменяются.

## Текущее состояние

- Агент электроэнергии получает текущий контекст и историю датчиков HA.
- PostgreSQL 18 работает в Docker на Debian: база smart_home, схема energy; 
- SMB-папка utility-import подключена к контейнеру: /home/yaha/utility-import/incoming → /files/utility-import.
- Реализован последовательный импорт нескольких PDF: чтение → извлечение текста → локальный JavaScript-парсер → PostgreSQL → удаление PDF после успешной записи.
- Используются energy.utility_documents, energy.utility_meter_readings и energy.utility_charges. 
- Energy — Receipt Context подключён к агенту; получение ответа по квитанциям подтверждено.

Работа импорта по расписанию отдельно не настроена.

Подробности: [STATUS.md](STATUS.md). План: [PLAN.md](PLAN.md).

## Работающая архитектура

```text
Чат / вызов workflow → Agent energy
  ├─ HA Read energy context → текущие показатели
  ├─ Energy History → HA_EnergyHistory → история
  └─ Energy — Receipt Context → PostgreSQL → квитанции

Windows → SMB → входная папка → n8n
  → PDF → текст → локальный парсер → PostgreSQL
  → удаление конкретного PDF после успешной записи
```

HA Read context через MCP остаётся отдельным workflow.

## Ограничения данных

- Текущий контекст группирует power, energy, voltage и current по помещениям и устройствам. Нечисловое состояние не считается нулём.
- История HA: один sensor за вызов, даты с часовым поясом, максимум 7 суток. completeness=not_verified не подтверждает полноту.
- доступна история примерно за месяц; Архивирование сырых показаний HA в PostgreSQL не запускаем.
- Показания, расход и начисления разделяются. Индивидуальное потребление и общее имущество не смешиваются.
- Ставки квитанции — актуального тариф и срок его действия.

## Импорт PDF и хранение

Отдельный тарифный справочник не создаём. Ставки берём из квитанций; расписание Т1–Т3 при реализации аналитики сверяем с официальным источником и сохраняем небольшой конфигурацией с часовым поясом и источником. 

## Оркестратор

Оркестратор обязателен в целевой архитектуре: единый диалог, вызов профильных агентов, уточнения и объединение сведений разных подсистем. Пока реализован только энергетический специалист. 

Расчёты остаются в профильных workflow. 

## Безопасность

Не публиковать токены, пароли, оригиналы квитанций, лицевые счета, ФИО, адреса и закреплённые персональные результаты. Гостевой SMB доступен только в доверенной локальной сети; подключившиеся клиенты могут менять и удалять файлы. Не публиковать SMB в интернет. Изменения гостевого входа и SMB-подписи Windows имеют клиентский масштаб.

Execute Command включён для удаления PDF и расширяет полномочия workflow. Удалять только конкретный проверенный путь внутри входной папки; файловое ограничение n8n не является песочницей shell-команд. Существующие экспорты с локальными адресами и служебными ссылками не считать прошедшими полный аудит.

Автоматическое удаление успешно импортированного PDF согласовано отдельно.
