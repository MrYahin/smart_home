## Квитанции через папку — решение от 6 ноября

Владелец самостоятельно получает документы и складывает их в существующую SMB-папку /home/yaha/utility-import/incoming, доступную n8n как /files/utility-import. Дальнейшую загрузку строим на существующем импорте PDF в PostgreSQL, без нового интерфейса. Автоматический запуск импорта по расписанию этим решением не подтверждается.

Целевой охват расширяется на отдельные квитанции за тепло, содержание жилья и интернет наряду с электричеством. Это требование, не отчёт о готовности парсеров: новые образцы, определение формата и полнота извлечения пока не проверены. Для каждого фактического формата предстоит проверить поставщика, вид документа, период и извлечение, затем при необходимости расширить разбор. Персональные примеры не публикуются в репозитории.

Целевая цепочка: существующая папка → определение формата → соответствующий разбор → PostgreSQL → документальный контекст агента УК. Сведения квитанций энергетическому агенту не передаются. Платежи и обращения не выполняются.

Требование к обработке: удалять только конкретный исходный PDF после успешного сохранения данных. Неизвестные форматы и ошибки не считать успешным импортом; файлы оставлять в папке. Начисления, баланс, задолженность, оплаты и сумму к оплате различать; пересекающиеся начисления разных документов автоматически не суммировать. Проверка исполнения этих требований на новых форматах ещё предстоит.

Получение документов из Комфорт-сити, МОЭК, mos.ru и Дом.ру через почту, API или автоматизацию кабинетов отложено. Публичные API и доступ к конкретным кабинетам не подтверждены; интеграции не реализовывались в рамках обсуждения.

Оставляем текущий чат n8n. Open WebUI — предпочтительное направление развития интерфейса, если оно упростит реализацию новых требований; для папочного импорта переход не требуется. Загрузка и выдача файлов непосредственно в чате этим обновлением не подключаются.

Согласованный упрощённый импорт сохраняется: без добавления дедупликации, промежуточного подтверждения, автоматических арифметических проверок, архива оригиналов или нового журнала ошибок. Повторная загрузка может создать дубль; изменение этих границ требует отдельного согласования.

## Изменение плана на 5 ноября

По решению владельца вместо немедленного диалогового профиля:

1. Сейчас предпочтения явно задаются владельцем и вручную вносятся в PostgreSQL. Ближайшие действия — начальное заполнение owner_profile.preferences и подключение чтения существующему оркестратору.
2. Автоматическое выявление привычек и запись из диалога, отдельный workflow подтверждений откладываются. Второй общий чат не создаётся.
3. После создания personal_assistant владелец помещает исторические данные о себе в RAG; затем рекомендации с оркестратором перестраиваются на получаемый персональный контекст, актуальные предпочтения и независимые данные домашних агентов.
4. PostgreSQL остаётся источником актуальных явно заданных предпочтений; история автоматически их не заменяет. Противоречия уточняются. Источники, даты и применимость учитываются, если известны. Оркестратор получает необходимый контекст, не весь архив.

Это решение о направлении, не результат внедрения. Интерфейс интеграции, технология RAG и миграции не выбраны. До переключения нужны проверка согласованных сценариев, сохранение текущих записей и возможность отката. Развитие умного дома не блокируется ожиданием personal_assistant.

## Ограничения данных и импорта

- HA: один sensor, максимум 7 суток; completeness=not_verified не подтверждает полноту. Ранее сообщалось примерно о месяце истории. Архив сырых данных отложен; месячные счётчики не складываются с накопительными.
- УК возвращает результат парсера, не полный PDF. Полнота задолженности, аванса, оплат, сроков, примечаний и оснований перерасчётов не подтверждена; null не равен нулю.
- Расчётный месяц не задаёт точный период. Применённая ставка не доказывает действующий тариф или расписание зон. Индивидуальные начисления, общее имущество и содержание жилья разделяются; итоги и перерасчёты не учитываются дважды.
- Импорт остаётся без дедупликации, промежуточного подтверждения, автоматических арифметических проверок и сводного отчёта. Возможны дубли и оставшийся после записи PDF при ошибке удаления. Импорт по расписанию не подтверждён.
- Полнота архива, отсутствие дублей, все варианты парсинга и обоснованность начислений не проверены.
