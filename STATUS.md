Это позволяет перейти к следующему этапу, но не доказывает готовность расчётов или устранение всех замечаний к опубликованному промпту.

По сообщению владельца, история доступна примерно за последний месяц, долгосрочная статистика HA не сохраняется. Причина не установлена. Долгосрочный архив датчиков в PostgreSQL отложен по решению владельца.

- База smart_home, отдельный пользователь n8n_app без административных прав.
- Пароль администратора передаётся файлом Compose secret; данные в постоянном volume.
- Порт PostgreSQL наружу не опубликован в подготовленной конфигурации.
- Сеть smart-home-storage закреплена в Compose n8n; сохранена n8n-docker_default. Владелец предоставил вывод обеих сетей.
- Подключение Postgres из n8n проверено владельцем. Внутренняя база n8n не переносилась.
- Схема energy и права n8n_app: USAGE, SELECT/INSERT/UPDATE; без CREATE и DELETE. Настроены права будущих объектов, создаваемых postgres.

Предоставлен SQL для energy.sensors и energy.readings. Их фактическое создание отдельно не подтверждено; автоматическое заполнение не запускалось и не планируется на текущем этапе.

Предоставлен SQL для energy.document_meter_readings и ручной загрузки пяти показаний из квитанции. Успешное выполнение и фактическое содержимое таблицы не подтверждены. До автоматического импорта нужно проверить её наличие и ранее загруженные записи. Привязка к документу пока основана на имени файла; дальнейшая схема требует проектирования.

Гостевой доступ не ограничивает импорт конкретным человеком. В ходе настройки Windows разрешён гостевой вход и предложено снять обязательность SMB-подписи; успешный доступ подтверждён, итоговые параметры клиента отдельно не предоставлены. Эти изменения имеют клиентский, а не исключительно папочный масштаб.

## PDF и тарифы

Квитанция проанализирована как пример структуры: показания, расход, ставки, начисления; три электрические зоны; индивидуальные и общедомовые строки. Персональные данные и значения конкретной квитанции в документацию не переносим.

Согласовано: единый автоматический workflow без подтверждения, проверки повторных файлов, содержательных автоматических проверок и сводного отчёта. Удаление PDF только после успешной транзакции записи. При ошибке файл остаётся; ошибка фиксируется. Ошибки удаления после записи учитываются отдельно. Повтор может создать дубли или конфликт; успешная запись не гарантирует правильности распознавания.

Не реализованы: workflow импорта, его журнал ошибок, схема начислений и тарифных интервалов, пакетный импорт двух лет, резервное копирование с проверкой восстановления. Полноценные SQL-миграции и Compose-снимки в репозиторий не добавлены.
