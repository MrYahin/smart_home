# Статус проекта — 25 октября 2026

## Основание и границы проверки

Проанализированы предоставленные владельцем экспорты HA-Read-context.json, Agent-energy.json и HA-Read-energy-context.json. Выполнен статический анализ конфигурации, а не запуск в n8n. В трёх экспортах active: true и пустой pinData; это не доказывает успешное выполнение или доступность сервисов.

Этот документ уточняет статус README от 22 октября: конфигурация агента электроэнергии уже существует. Отсутствие агента больше не является открытым вопросом. Успешный сквозной вызов всё ещё требует проверки. Исходные экспорты этим изменением не публикуются.

## Целевая архитектура

Многоагентный умный дом: один оркестратор координирует специализированных агентов подсистем. Первый рассматриваемый агент — электроэнергия. Экспорт оркестратора не предоставлен; его наличие или отсутствие во всей рабочей среде не установлено.

## Реальная конфигурация по экспортам

```text
Чат или вызов из другого workflow
    → Agent energy: AI Agent
        ├─ Google Gemini Chat Model
        ├─ Simple Memory
        └─ инструмент Call 'HA Read energy context'
            → HA Read energy context
                → POST /api/template
                → filter_energy_data
                → areas → devices → readings

Отдельная ветка:
Ручной запуск или вызов из другого workflow
    → HA Read context
        → MCP Client / GetLiveContext
```

### Agent energy

- Есть chat trigger и вход из другого workflow с message и sessionId.
- Текст запроса выбирается как message ?? chatInput.
- Подключён Google Gemini Chat Model; конкретная модель явно не задана в параметрах экспорта.
- Подключена Simple Memory с ключом energy: + sessionId.
- Workflow Tool ссылается на ID предоставленного HA Read energy context: связь совпадает по экспортам.
- Промпт требует получить актуальные данные инструментом перед ответом о текущем состоянии. Это инструкция модели, а не доказательство фактического вызова.
- Промпт описывает areas/devices/readings/unassigned, единицы, value: null, месячные счётчики и запрет двойного подсчёта.
- Предписаны краткие ответы на русском и только чтение данных. Подключённый инструмент собирает показатели; инструментов переключения в этом экспорте нет.

### HA Read energy context

- Ручной триггер и триггер вызова из другого workflow ведут к одному HTTP Request.
- POST /api/template использует bearer credential; HTTP Request настроен executeOnce.
- Jinja отбирает sensor по единицам: W, kW, Wh, kWh, V, A и согласованным русским обозначениям.
- Шаблон получает entity_id, имя, state, unit, device_class, state_class, device_id, device_name, area_id, area_name, last_updated.
- filter_energy_data разбирает ответ, устраняет повторения по entity_id, преобразует числовые значения и группирует по помещениям и устройствам.
- Нечисловой статус сохраняется в state, value становится null.
- Итог содержит received_at, счётчики по типам, устройствам и помещениям, диагностику отсутствующих привязок и areas.
- Помещения без привязки помещаются в группу «Без помещения»; сущности без устройства — в unassigned своего помещения.
- Единицы не пересчитываются, значения не суммируются.

Известные месячные связи:

| Месячный счётчик | Источник |
|---|---|
| sensor.sockets_kitchen | sensor.sockets_kitchen_energy |
| sensor.sockets_bath | sensor.sockets_bath_energy |

Эти связи используются для energy_role и резервной привязки к устройству и помещению источника. Месячный и исходный счётчики не складываются. Период накопления исходных счётчиков пока не установлен.

### HA Read context

- Сохранён отдельный MCP-workflow с GetLiveContext.
- Есть ручной запуск и вызов из другого workflow.
- Возвращается ответ MCP без дополнительного парсинга.
- В предоставленном Agent energy нет ссылки на этот workflow.
- MCP удалён из цепочки электрических показателей, но не из проекта целиком.

## Что требует проверки или исправления

1. В промпте Agent energy требуется искать switch, но подключённый Energy Context возвращает только sensor. Нужно либо ограничить обещания агента показаниями, либо отдельно добавить read-only источник статусов выключателей. Отсутствие switch в ответе не означает, что устройство выключено.
2. Chat trigger содержит public: true. Перед использованием проверить фактическую доступность чата и настройки аутентификации. Экспорт сам по себе не доказывает открытый доступ из интернета.
3. Проверить sessionId для обоих входов. Нет проверки отсутствующего или пустого ID; при отсутствии значения ключ памяти может стать energy:undefined. Проверить изоляцию двух разных сессий.
4. Проверить реальный ответ HTTP Request: options пустой, явный формат ответа в экспорте не закреплён. Парсер поддерживает JSON-объект и строку в data/body, но совместимость нужно подтвердить запуском.
5. Фильтрация измерений выполняется по единицам, а не по полному каталогу назначений и покрытия. Это ещё не каталог измерений и не основание считать общий расход квартиры.
6. Вызов из другого workflow передаёт message/sessionId, но отдельного структурированного контракта результата агента в экспорте нет. Его нужно согласовать перед подключением оркестратора.
7. availableInMCP: true задано во всех трёх workflow. Это настройка публикации инструментов, а не признак того, что каждый workflow использует MCP для чтения HA. Проверить необходимость экспонирования и права доступа.
8. В этих трёх workflow нет истории, тарифного хранилища, импорта PDF, расчёта стоимости, прогноза, предложений или расписания отчётов. Их наличие в других workflow не проверено.

## Следующие действия

### Сейчас: завершить этап текущего контекста

- Уточнить промпт относительно switch: не обещать данные, которых инструмент не возвращает.
- Проверить доступ к чату, sessionId и изоляцию памяти.
- Выполнить сквозные проверки: чат → агент → инструмент → ответ; отдельно вызов агента из другого workflow.
- Проверить запрос по одному устройству, по помещению, по месячному расходу, по отсутствующему показанию и по истории, которой пока нет.
- Убедиться, что агент не выдумывает историю, общий расход квартиры и стоимость.
- Сохранить обезличенный пример фактического ответа и результаты проверок.
- Подготовить безопасные копии экспортов для версионирования: убрать локальные адреса, служебные метаданные и ссылки на credentials; описать переназначение credentials и workflow ID после импорта. Исходную рабочую конфигурацию не менять автоматически.

Критерий готовности: оба входа работают, агент действительно вызывает инструмент для текущих данных, память разделена по сессиям, ограничения корректно отражены в ответах.

### Затем: каталог измерений

Для расчётных счётчиков зафиксировать entity_id, устройство, помещение, назначение, единицу, период накопления и сбросы, источник, покрытие и правила суммирования. Определить наличие общего счётчика квартиры, отдельные группы и пересечения. Не требовать от пользователя вручную заносить все датчики: техническую основу получить из контекста, вручную уточнить только смысл и покрытие.

### После каталога

1. HA — Energy History: один проверенный счётчик, доступные периоды, пропуски, сбросы и часовой пояс.
2. Историческое хранилище и тарифы с датами действия и зонами суток. PDF прошлых лет: извлечение → проверка → подтверждение → сохранение. RAG пока не нужен.
3. Energy — Calculate: JavaScript-расчёты расхода, стоимости и сравнений, проверенные на известных примерах.
4. Простой прогноз до конца месяца с проверкой на прошлых периодах и указанием покрытия; не переносить данные одной розетки на весь дом.
5. Energy — Proposals: данные, гипотеза, необходимые проверки и ожидаемый эффект с допущениями.
6. Суточные и месячные отчёты, уведомления об отклонениях. Автоматизации и управление нагрузками — только после подтверждения.
7. Контракт агента и оркестратор: вход, результат, ошибки, ограничения и подтверждения; далее подключение других подсистем.

## Безопасность публикации

В просмотренных полях экспортов есть ссылки на credentials, но не значения токенов. Также присутствуют локальный адрес HA, webhook ID, instanceId и внутренние идентификаторы. Это не равнозначно утечке паролей, но исходные экспорты не публикуются автоматически. В этом документе приватные адреса и служебные идентификаторы не приводятся.
