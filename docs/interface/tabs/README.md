# Вкладки дашбордов Home Assistant

Это каталог **конфигураций и описаний существующих вкладок по назначению**, присылаемых владельцем. Он не создаёт вкладки в запущенном Home Assistant и не является экспортом рабочего дашборда.

## Принцип

- Для **каждой предоставленной вкладки** создавать `docs/interface/tabs/<tab_id>/`, где `<tab_id>` — согласованное устойчивое имя.
- В `README.md` этой папки фиксировать название вкладки в Home Assistant, её назначение, набор профильных агентов, состав карточек и место карточки рекомендаций.
- Присланный YAML сохранять в `cards.yaml` (или отдельно `dashboard.yaml`, если передана конфигурация вкладки целиком), сохраняя исходные сущности и структуру без предположений; изменения показывать явно.
- В корневом [README.md](../../../README.md#интерфейс-системы) сразу обновлять **только раздел «Интерфейс системы»**: указывать новые вкладки, связи с агентами и принятые решения по отображению.
- Перед публикацией проверять отсутствие секретов, токенов, адресов доступа и персональных данных в присланных карточках; не публиковать чувствительные данные.
- Главная вкладка содержит приоритеты **оркестратора**, а остальные — рекомендации по назначению вкладки, даже если их сформировали несколько агентов.
- Статусы работы подсистем хранятся в `docs/status/`. Этот каталог — про **интерфейс**, а не про внедрение агентов.

## Правила пошаговой доработки карточек

Владелец **самостоятельно** редактирует карточки в Home Assistant по последовательным инструкциям ассистента. На каждый шаг — объяснение цели, точный участок YAML или путь в редакторе, изменение, ожидаемый результат, проверка и при необходимости откат. **Следующий шаг — после подтверждения результата владельцем.** Сохранение YAML в GitHub не вносит его в работающий HA.

Подробный процесс: [правила проекта](../../../AGENTS.md#пошаговое-изменение-интерфейса-home-assistant) и [решение об интерфейсе](../../decisions/interface-files.md#порядок-изменения-карточек-home-assistant).

## Модель рекомендаций

Хранилище первого этапа — **Home Assistant Local To-do** с двумя состояниями `needs_action` / `completed`. Срок хранения завершённых рекомендаций — до 365 дней, с отдельной выборочной очисткой. Принятие задачи, откладывание, фильтрация и отображение следующей рекомендации требуют автоматизаций; это не возможности готовой карточки «из коробки».

Полное согласованное поведение: [раздел «Интерфейс системы» в корневом README](../../../README.md#интерфейс-системы).
