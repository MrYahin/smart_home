# Решение: интерфейс и файлы

**Зафиксировано 6 ноября 2026.** Детальные обязательные ограничения для ИИ остаются в корневом [AGENTS.md](../../AGENTS.md).

## Диалог

Один общий чат в n8n и один оркестратор. Не разрабатывать отдельный чат, Streamlit или собственный UI без нового решения владельца. Open WebUI — предпочтительное **направление рассмотрения** при заметном росте требований, но не запланированная немедленная миграция. Open WebUI — пользовательский слой, оркестрация остаётся в n8n.

Прежде чем расширять чат n8n сложной функциональностью, сравнивать его стоимость настройки и сопровождения с Open WebUI + минимальным адаптером. Конкретные возможности выбранной версии проверять, не обещать их по умолчанию.

## Файлы в диалоге

Входное вложение ещё не означает, что модель получила содержимое. Для Excel и других форматов нужны извлечение, валидация, сохранение вопроса и `sessionId`; не вызывать агента для каждой строки без необходимости. Вложение относится к текущему запросу, а не к постоянной БД или RAG, если владелец отдельно не разрешил сохранение.

Исходящий файл требует фактической генерации, хранения и безопасной выдачи ссылки. Бинарный объект внутри n8n не гарантирует скачивание в чате. Персональные выгрузки — с проверкой доступа, сроком действия и удалением временных копий; не выдумывать ссылки.

## Квитанции ЖКХ

Для квитанций сохраняется существующий **папочный** способ подачи через SMB. Отдельный UI и автоматическая загрузка через сайты поставщиков пока не входят в это решение. [Схема импорта](../infrastructure/pdf-import.md).

Этот документ задаёт требования и варианты; факт их реализации находится только в [статусах](../status/README.md).
