# PostgreSQL и схема хранения

## Логическая модель

Используется база `smart_home`. Для документальных сведений предусмотрена схема `energy` с таблицами:

- `energy.utility_documents` — документ и `payload` результата парсинга;
- `energy.utility_meter_readings` — показания;
- `energy.utility_charges` — начисления.

Для явно заданных предпочтений предусмотрена схема `owner_profile`, таблица `owner_profile.preferences`:

| Поле | Тип / правило |
| --- | --- |
| `id` | `BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY` |
| `preference_key` | `TEXT NOT NULL UNIQUE` |
| `preference_value` | `JSONB NOT NULL` |
| `description` | `TEXT` |
| `created_at` | `TIMESTAMPTZ NOT NULL DEFAULT now()` |

Предпочтения задаются владельцем; автоматическая модификация по тексту диалога не разрешена. Структура области и срока `preference_value` подлежит отдельному согласованию.

## Контракты и ограничения

- Прочитанный payload — не полный PDF, и отсутствие свойства не является нулём.
- Нельзя молча объединять документы за одинаковый месяц или суммировать повторяющиеся суммы.
- Разграничить право читать данные и право менять их; хранить учётные данные вне репозитория.
- SQL-миграции, резервные копии и проверка восстановления оформлять и тестировать отдельно.

Подтверждённая конфигурация, права роли `n8n_app`, состав миграций и расхождения с экспортами — в [статусе инфраструктуры](../status/infrastructure.md).
