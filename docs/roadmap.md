# Общая дорожная карта

План описывает **порядок развития**, не отчёт о выполнении. Проверенные факты и фактические блокеры — в [status/](status/README.md); детальные задачи — в `agents/<id>/ROADMAP.md`.

1. **Персонализация в PostgreSQL:** владелец согласует и вручную вносит начальные предпочтения в `owner_profile.preferences`, затем оркестратор получает право их читать. Не создавать автоматическое изменение профиля из диалога.
2. **Квитанции ЖКХ:** расширять безопасный папочный импорт на отдельные документы за тепло, содержание жилья и интернет. Проверять каждый формат и полноту извлечения; развивать документальный контекст УК.
3. **Энергетика HA:** сформировать каталог датчиков, исключить дубли, исследовать качество истории, добавить корректные расчёты нагрузок и зон при наличии подтверждённых правил.
4. **Взаимодействие агентов:** структурировать ответы и качество данных, аккуратно сравнивать независимые источники, формировать обоснованные предложения по комфорту и затратам.
5. **Другие домашние подсистемы:** добавлять профильных агентов только по реальным устройствам и понятной пользе. Для каждого — отдельный каталог, ROADMAP и статус.
6. **Результат для владельца:** готовить 1–3 приоритетных предложения ежедневно и выводить показатели в существующий HA-дашборд с вечерним обновлением.
7. **Будущий personal_assistant:** после его готовности использовать релевантный исторический RAG вместе с актуальными предпочтениями PostgreSQL, сохраняя источники, даты и возможность отката.
8. **Надёжность:** отдельно согласовать резервное копирование с проверкой восстановления, диагностику, журнал ошибок и расширение прав.

Изменения выполняются пошагово самим владельцем. Прототип не равен введённой в эксплуатацию функции; затраты и окупаемость показываются только при наличии обоснованного расчёта.
