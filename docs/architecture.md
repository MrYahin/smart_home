# Архитектура Smart Home

## Назначение

Домашняя система собирает факты от специализированных подсистем и выдаёт рекомендации по **экономии и комфорту**. Оркестратор n8n владеет маршрутизацией; профильные агенты не должны имитировать доступ к данным других агентов.

```text
Пользователь → чат n8n → Оркестратор (My workflow)
                          ├── Энергетический агент
                          │     ├── HA Read energy context → Home Assistant
                          │     └── Energy History → HA_EnergyHistory → HA
                          └── Агент УК
                                └── Контекст квитанций → PostgreSQL

Владелец → SMB-папка → n8n импорт PDF → парсер → PostgreSQL

(Будущее) актуальные предпочтения PostgreSQL + RAG personal_assistant
         → релевантный персональный контекст → оркестратор
```

## Независимые области данных

| Область | Ответственный | Источник |
| --- | --- | --- |
| Электрические датчики и их история | [Energy](../agents/energy/README.md) | Home Assistant |
| Сведения квитанций ЖКХ | [UK](../agents/uk/README.md) | PostgreSQL, результат импорта PDF |
| Смешанные вопросы, сопоставление и рекомендации | [Orchestrator](../agents/orchestrator/README.md) | Ответы агентов и позже актуальные предпочтения |
| Исторический персональный контекст | Будущий personal_assistant | RAG, по отдельному решению владельца |

Квитанции и их пересказ **не передаются** энергетическому агенту. Сравнения допустимы только при совместимости источников, периодов, единиц и охвата. `null` и отсутствие данных не равны нулю.

## Единый контракт на перспективу

Предлагаемые обязательные смысловые поля ответа: `status`, `source`, `scope`, `period`, `data`, `quality`, `limitations`; при наличии `observed_at`, `document_id`, `units`. Это **проектируемое соглашение**, не утверждение о готовности всех workflow. Точный JSON-контракт согласуется перед изменениями n8n.

## Изменения и полномочия

Чтение данных не даёт права на управление устройствами, платежи или запись предпочтений. Не создавать второй общий чат или второй оркестратор в UI. Архитектура интерфейса, персонализации и импорта фиксируется в [решениях](decisions/interface-files.md) и [решении о профиле](decisions/personalization.md). Фактическая готовность — только в [статусах](status/README.md).
