# Архитектура Smart Home

## Назначение

Домашняя система собирает независимые факты от профильных агентов и помогает владельцу не только экономить ресурсы, но и **постоянно улучшать комфорт, безопасность, надёжность и эксплуатацию дома**.

**Оркестратор n8n** — единая точка общего диалога, маршрутизации и будущего **Home Improvement Planner**. Новый координирующий чат или отдельный второй оркестратор не создаётся.

## Текущее подтверждённое направление (по документации и подтверждениям владельца)

```text
Пользователь → чат n8n → Оркестратор (My workflow)
                          ├─ Энергетический агент → HA Read energy context / Energy History → HA
                          └─ Агент УК → Контекст квитанций → PostgreSQL

Владелец → SMB-папка → импорт PDF n8n → парсер → PostgreSQL
```

Работающая система удалённо не проверялась. Текущие ограничения и расхождения экспортов: [статусы](status/README.md).

## Планируемое расширение

```text
Профильные источники / оборудование / подтверждения владельца
  ├─ Энергетический        ├─ Климат/HVAC         ├─ Растения
  ├─ Агент УК              ├─ Автомобиль          ├─ Лекарства
  ├─ Сервис                └─ Безопасность
  │
  └─ Проверяемые наблюдения, потребности, ограничения
              ↓
        Оркестратор n8n
        ├─ маршрутизация и независимые факты
        ├─ Home Improvement Planner (проект)
        │   ├─ новая покупка
        │   ├─ модернизация
        │   └─ будущая активность / профилактика
        ├─ решения владельца и контроль результата (проект)
        └─ согласованные потребности → Агент закупок (проект)
                                           ↓
                                 предложения / корзины
                                 → подтверждение владельца

(Будущее) актуальные предпочтения PostgreSQL + RAG personal_assistant
           → релевантный персональный контекст → оркестратор
```

## Ответственность и данные

| Область | Ответственный | Основные источники |
| --- | --- | --- |
| Электрические показания и история | [Энергетический](../agents/energy/README.md) | HA |
| Квитанции, документальные начисления | [УК](../agents/uk/README.md) | Сохранённый результат парсинга PDF в PostgreSQL |
| Микроклимат | [Климат](../agents/climate/README.md) | Планируемые датчики HA и погодные данные |
| Растения | [Растения](../agents/plants/README.md) | Карточки растений и подтверждённые датчики |
| Автомобиль | [Автомобиль](../agents/vehicle/README.md) | История ТО и пробег, позже телеметрия |
| Лекарства и приём | [Лекарства](../agents/medications/README.md) | Подтверждённые назначения, приватный журнал |
| Эксплуатация оборудования | [Сервис](../agents/service/README.md) | Инвентаризация, диагностика, события HA |
| Бытовые угрозы | [Безопасность](../agents/security/README.md) | Согласованные аварийные датчики |
| Подбор товаров и запасов | [Закупки](../agents/procurement/README.md) | Согласованные потребности и проверенные предложения |
| Интеграция, план улучшений и решения | [Оркестратор](../agents/orchestrator/README.md) | Выводы агентов + актуальные предпочтения |

Все области кроме текущих подтверждений энергетики и УК — **планируемые**; их подключение и функционирование не проверены.

## Проектируемый контракт

Базовые поля ответов: `agent_id`, `status`, `source`, `scope`, `period`, `data`, `quality`, `limitations`, при наличии `observed_at`, `units`, `document_id`. Для предложений улучшений дополнительно: тип, доказательства, альтернативы, риск, польза, оценка затрат, уверенность и необходимость одобрения. Конкретная схема JSON **ещё не реализована**.

Сопоставления допустимы только для совместимых периодов, единиц и охвата. Квитанции и пересказ УК **не передавать** энергетическому агенту. Медицинские сведения минимизировать; не передавать их всем агентам через общую память. `null` и отсутствие данных не равны нулю.

## Полномочия

Чтение и формирование предложения не дают права изменить устройство, сделать заказ, оплатить, сообщить третьей стороне или записать предпочтение. Сценарии аварийного управления требуют заранее принятого отдельного решения и проверки. Сохранять существующий чат n8n, сравнивать новые требования с Open WebUI только при реальной необходимости.
